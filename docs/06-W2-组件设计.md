## 0. W-1 结论驱动的 W-2 范围
W-1 确认 Qwen3-TTS 训练有 **3 处与文本 SFT 不同**（不止 Preprocessor/Loss）：
1. **数据**：双通道 `input_ids[B,T,2]` + `codec_ids[B,T,16]` + 4 mask + `ref_mels` + `codec_0_labels`（非 `Trajectory+user_data` 的简单拼接）。
2. **Loss**：2 段式 `CE(码本0) + 0.3×CE(码本1-15)`（非 16 路 CE）。
3. **forward 编排**：speaker_encoder 前置 + 手动组装 inputs_embeds + 2 段 forward（非 `model(input_ids=...)` 单次）。

W-2 覆盖 ① 数据（Processor + 数据构建器，已实现+CPU 单测）+ ③ forward 编排（逻辑骨架+集成方案）。② Loss 留 W-4。

## 2. 数据流设计（manifest → Twinkle InputFeature）
```
manifest.jsonl 行
  → Qwen3TTSProcessor.preprocess(row) (= MultiCodebookPreprocessor)  # 产 Trajectory(messages=[user:text], user_data=[audio_codes, ref_audio, language])
  → [已实现] Qwen3TTSTemplate._encode_messages(traj)  # 读 user_data，文本 tokenizer 编码（TEXT_IDS_TRIM=5 去尾部闭合/重开 token）+ build_qwen3_sample → 双通道 InputFeature
  → [已实现] Qwen3TTSInputProcessor：collate_fn 2D 强制 stack + ref_mels cat + to_transformers_dict 白名单
  → DataLoader → (forward 编排) qwen3_tts_forward_step
```
- `TTSMultiCodebookProcessor` 只产 `Trajectory`（薄层）；重活在 `Qwen3TTSTemplate`（override `_encode_messages`，调 `build_qwen3_sample`）。
- 后管线两处冲突（W-3 已覆写，方案 B 保留管线）：
  - `_add_attention_fields`：基类 `np.ones_like(input_ids)` 对 2D `[T,2]` 产 `[T,2]`（错；forward 要 `[T]`）→ 覆写为 1D 走基类、2D 产 `[T]` mask + position_ids + length。
  - `_roll_labels`：基类无条件访问 `input_feature['labels']`，但 Qwen3-TTS 不用标准 `labels`（用 `codec_0_labels`，shift 由 forward 编排 `[:, 1:]` 做镜像官方）→ 覆写为 **no-op**（避免 KeyError + 重复 shift）。`codec_ids[T,16]` 是输入非 label、不进 `labels` 键，2D 滚轴障碍不触发。
- InputProcessor 3 个结构障碍的处理：
  - `selective_log_softmax` 单码本 → forward 编排不走 `logps` 路径（自算 loss），不受影响。
  - 2D concat → `input_ids[T,2]`/`codec_ids[T,16]` 需强制 `stack`（`pad_and_stack_tensors(concat=False)`，非 padding-free concat）；masks 补 channel 维 `[B,maxT,1]`；`ref_mels` 沿时间 `cat`（不 pad）；注册进 `padding_map`/白名单。✅ W-3 已落。
  - `_roll_labels` → 见上，已覆写 no-op。

## 3. forward 编排集成方案（W-2 附加，首要难点）
官方 4 步（`tts/forward.py` 已移植）超出 `forward_backward(task='causal_lm')` 单次 forward。3 个集成选项（详见 `tts/forward.py` 末）：
- **A（推荐）**：自定义 `TransformersModel` 子类，override `forward_backward/calculate_loss`，保留 clip_grad/梯度累积/metric 抽象 + 多 LoRA 透传。cookbook 仍调 `model.forward_backward(inputs=batch)`。
- **B**：自定义 task Patch（仿 `TransformersFusedCEPatch`），在 `_resolve_task_context` 注册 `task='qwen3_tts'`，patch 劫持 talker.forward 做 2 段+speaker 前置。
- **C**：cookbook 直接调 `qwen3_tts_forward_step` + `accelerator.backward`（最接近官方，但放弃 Twinkle 抽象）。

→ 倾向 A。**W-5 去机房用真实 Qwen3-TTS 权重 + NPU 实测后敲定**（选项 A/B 的 patch 时机/多 LoRA 透传需实测验证）。

## 4. LoRA 范围（已与用户确认）
- 挂：`talker`（`codec_head`、`q/k/v/o/gate/up/down_proj`、`text_projection`）+ `code_predictor`（各 `lm_head[i]`、`q/k/v/o/gate/up/down_proj`、`small_to_mtp_projection`）；或简化 `'all-linear'`。
- 冻结：`speaker_encoder`（本就 detach）、`codec_embedding`/`text_embedding`（talker）、code_predictor 各 `codec_embedding[i]`。
- 偏离官方全量 SFT 基线；保留 clone 推理（不做 custom_voice 说话人槽）。

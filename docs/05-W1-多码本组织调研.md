> 本文件固化 issue #279 工作项 **W-1（调研多码本 token 在序列里怎么组织）** 的全部结论，防止后续会话重复造轮子。
> 术语见 `docs/01-术语表与基础概念.md`；路线见 `docs/00-总体方案.md`；硬规则见 `AGENTS.md`。

## 0. 一句话结论

Qwen3-TTS 的多码本是 **RVQ 16 码本**（shape `[T, 16]`），但训练**不是**"16 个并行 head 各算一路 CE 求和"，而是 **2 段式层级架构**：
- **Talker**（Qwen3 AR-LM）自回归预测 **codebook 0**（标准 shift+CE）；
- **Code predictor**（深度 Transformer）基于 Talker hidden 逐帧预测 **codebooks 1-15**（15 个并行头，逐帧、带位置偏移的 CE）；
- 总 loss = `talker CE(码本0) + 0.3 × code_predictor CE(码本1-15)`。

且官方训练循环**不走**标准 `model(input_ids=...)`，而是手动组装 `inputs_embeds` + speaker_encoder 前置 + 2 段 forward。这直接影响 W-2/W-3/W-4 的设计——见第 6 节。

## 2. 码本组织（shape / RVQ / 码本数）

### 2.1 audio_codes shape = `[T, 16]`
- `prepare_data.py`：`Qwen3TTSTokenizer.encode(audios).audio_codes` → 每条一个 tensor，`.cpu().tolist()` 存进 manifest 的 `audio_codes` 字段。
- `dataset.py` `__getitem__`：`audio_codes = torch.tensor(audio_codes, dtype=torch.long)`，注释明确 `# t, 16`。
- `collate_fn`：`codec_ids = torch.zeros((b, t, 16), dtype=torch.long)`；`audio_codec_0 = data['audio_codes'][:, 0]`（取第 0 列=codebook 0，所有帧）。
- **结论：每帧 16 个码本，组织为 `[T, 16]`（帧 × 码本）；第 0 列是主码本（codebook 0），1-15 列是残差码本。**

### 2.2 num_code_groups = 16（对 12Hz 模型）
- 配置类默认 `num_code_groups=32`（`configuration_qwen3_tts.py`），但 **12Hz 模型实际为 16**，依据三重确认：
  1. `sft_12hz.py` 输入嵌入循环 `for i in range(1, 16)`（码本 1-15）；
  2. `dataset.py` `codec_ids` 第二维=16；
  3. `forward_sub_talker_finetune` 断言 `codec_ids.shape[1] == self.config.num_code_groups`（`modeling_qwen3_tts.py:1617`），而 sft 传入的 `codec_ids[codec_mask]` 第二维=16 ⇒ `num_code_groups=16`。
- ⇒ **codebook 0（Talker）+ codebooks 1-15（Code predictor 15 个并行头）= 16 码本**。Code predictor 的 `lm_head`/`codec_embedding` 各是 `num_code_groups - 1 = 15` 个 `ModuleList`。

> 待确认（阶段0 去机房下权重后）：读模型的 `config.json` 直接看 `num_code_groups` 字段，最终敲定。目前 16 已是强证据。

### 2.3 帧率与词表
- 帧率 **12Hz**（≈12.5 帧/秒）；10 秒音频 ≈ 120 帧 × 16 码本。
- 词表：Talker `codec_head` 输出维度=`config.vocab_size`（codec 词表，特殊 token id 到 4205，故 vocab ≥ 4206；默认 3072 仅为配置默认值，以实际 config.json 为准）。Code predictor `lm_head` 输出=`code_predictor_config.vocab_size`（默认 2048）。

## 3. 模型结构（三大子模块）

顶层 `Qwen3TTSForConditionalGeneration`（`modeling_qwen3_tts.py:1813`）组合三部分；**顶层无 `forward`，训练直接调 `model.talker(...)`**（sft_12hz.py 即如此）。

### 3.1 Talker（`Qwen3TTSTalkerForConditionalGeneration`，~1.7B，AR-LM）
- 骨干 `Qwen3TTSTalkerModel`（`:1427`）：Qwen3 解码器，20 层、hidden 1024、GQA（16 注意力头 / 2 KV 头）。
- `codec_embedding`：**单个** `nn.Embedding(vocab_size, hidden_size)`（`:1441`）——码本 0 输入嵌入。`get_input_embeddings()` 返回它（`:1447`）。
- `text_embedding`：`nn.Embedding(text_vocab_size, text_hidden_size)`（`:1442`）→ 经 `text_projection`（`Qwen3TTSTalkerResizeMLP`，`:1575`）升到 hidden_size。
- **`codec_head`**：`nn.Linear(hidden_size, vocab_size, bias=False)`（`:1579`）——**码本 0 输出头**。⚠️ 源码里 `_tied_weights_keys=["lm_head.weight"]`、`get_output_embeddings` 返回 `self.lm_head` 是**死代码/遗留**，Talker 从未实例化 `self.lm_head`；实际输出头是 `codec_head`。
- `code_predictor`：子模块（见 3.2）。
- `forward`（`:1636`，`@can_return_tuple`）：`codec_head(hidden_states) → logits`（`:1727`）；`loss = self.loss_function(logits, labels, vocab_size)`（`:1731`）；返回 `Qwen3TTSTalkerOutputWithPast`，其中 `hidden_states=(outputs.hidden_states, codec_ids)`（`:1738`，供 sub-talker 取用）。

### 3.2 Code predictor（`Qwen3TTSTalkerCodePredictorModelForConditionalGeneration`，深度 Transformer）
- 5 层小 Transformer，hidden 1024、16 注意力头 / 8 KV 头。
- `codec_embedding`：`nn.ModuleList` of `num_code_groups-1=15` 个 `nn.Embedding`（`:1031`）——码本 1-15 输入嵌入。
- `lm_head`：`nn.ModuleList` of `15` 个 `nn.Linear(hidden, vocab_size)`（`:1168`）——码本 1-15 输出头。
- `small_to_mtp_projection`：把 Talker hidden 投影到 Code predictor hidden（尺寸不同时是 `nn.Linear`，相同时 `Identity`）。
- `forward_finetune`（`:1233-1247`）：
  1. `inputs_embeds = small_to_mtp_projection(inputs_embeds)`；
  2. 跑 5 层 Transformer（**沿码本轴**，不是时间轴；`forward_sub_talker_finetune` 一次喂 `[N,16]+[N,H]` 向量化、非逐帧循环，W-4 读源码确认）；
  3. `logits = [lm_head[i-1](hidden[:, i]) for i in range(1, num_code_groups)]`，`torch.stack(dim=1)` → `[B, 15, V]`（注意每个头读 `hidden[:, i]`，**位置偏移/delay**：头 i-1 用位置 i 的 hidden 预测码本 i）；
  4. `loss = self.loss_function(logits, labels=codec_ids[:,1:], vocab_size)`。
- `forward_sub_talker_finetune`（在 Talker 上，`:1612-1633`）：**向量化**（非逐帧循环，W-4 读源码确认），输入 `codec_ids[N,16]`（N=批次目标帧总数，全码本）+ `talker_hidden[N,hidden]`（Talker 各目标帧 hidden）；组装 `[N,16,hidden]`（pos0=talker_hidden，pos1=码本0 emb，pos2..=各码本 emb）→ 调 `code_predictor.forward_finetune(labels=codec_ids[:,1:])` → 返回 `(logits[N,15,V], loss)`。

### 3.3 Speaker encoder（`Qwen3TTSSpeakerEncoder`，ECAPA-TDNN）
- 仅当 `tts_model_type=="base"` 时实例化（`:1822-1825`）；CustomVoice/VoiceDesign 模型为 `None`。
- `mel_dim=128, enc_dim=1024, sample_rate=24000`（ref 音频 24kHz）。
- `ref_mels → speaker_encoder → speaker_embedding [B, enc_dim]`。
- 训练时输出 `.detach()`（冻结，不反传）；官方还会把 target speaker_emb 写进 `codec_embedding.weight[3000]`（新增说话人行）+ 改 config 成 `custom_voice`——这是把 Base 变成"命名说话人"模型的路径，**本项目走 clone 推理，可不做此步**（见第 7 节）。

### 3.4 ⚠️ 消歧：codec ≠ code_predictor（名字像，完全不同的东西）

初学易混，专列一节。"codec" 与 "code_predictor" 都带 "code"，但一个在 LM **外面**、一个在 LM **里面**：

| | codec（编解码器） | code_predictor（码本预测器） |
|---|---|---|
| 是什么 | 语音 tokenizer `Qwen3-TTS-Tokenizer-12Hz`，**独立模型** | TTS-LM **内部**子模块（5 层深度 Transformer） |
| 在哪 | **不在 1.7B 模型里**（单独加载，`speech_tokenizer`） | **在 1.7B 里**（talker 的子模块） |
| 干什么 | wav ↔ audio_codes 互转（离线编码 + 推理解码） | 看 talker 主旋律，补写码本 1-15 |
| 训不训 | **不训**（冻结，见 `docs/02` §3） | **训**（LoRA 挂它） |

**两个维度，别混着说：**

- **维度 A（管线两模型，粗框）**：`文字 → [TTS-LM] → audio_codes → [codec] → wav`。这里"TTS-LM"是黑盒，"codec"指外面那个独立 tokenizer。
- **维度 B（打开 TTS-LM 黑盒，三件套）**：`TTS-LM = talker + code_predictor + speaker_encoder`。这里"code_predictor"指 LM 内部补码本的小模型。

之前"两阶段 talker+codec"多是**维度 A** 的粗框说法（把 TTS-LM 当黑盒）；W-1 说"两段 talker+code_predictor"是**维度 B**（LM 内部前向两段）。两者不矛盾，只是名字撞了容易混。

```
          ┌── TTS-LM (1.7B, LoRA 微调) ──────────────────────┐
文字 → talker ─┤  预测码本0 → code_predictor 预测码本1-15      │
          └── speaker_encoder 提声纹(冻结) ───────────────────┘
                          ↓ 输出 audio_codes (16 码本)
                    codec (独立, 不训)  ← 不在 1.7B 里
                          ↓ 解码
                        wav 声音
```

**一句话**：codec 在 LM 外面（管 wav↔token，不训）；code_predictor 在 LM 里面（管残差码本，要训）。

## 4. 数据格式（官方 `collate_fn` 产出，W-2 镜像源）

`dataset.py` 的 `collate_fn` 对每个 batch 产出（`B`=batch，`T`=padding 后序列长）：

| 字段 | shape | dtype | 含义 |
|---|---|---|---|
| `input_ids` | `[B, T, 2]` | long | **双通道**：`[:,:,0]`=文本 token（Qwen3 文本词表，151xxx 段）；`[:,:,1]`=codec token（codebook 0，codec 词表） |
| `codec_ids` | `[B, T, 16]` | long | 全码本（喂 Code predictor） |
| `text_embedding_mask` | `[B, T, 1]` | bool | 文本嵌入有效位 |
| `codec_embedding_mask` | `[B, T, 1]` | bool | codec 嵌入有效位（position 6 置 False，留给 speaker emb） |
| `codec_mask` | `[B, T]` | bool | 哪些位置是目标音频帧（取 hidden/codec_ids 用） |
| `attention_mask` | `[B, T]` | long | 因果注意力 mask |
| `codec_0_labels` | `[B, T]` | long | codebook 0 的 label，-100 mask（非音频帧置 -100） |
| `ref_mels` | `[batch, mel_frames, 128]`（cat dim=0） | float | 参考音频 mel（喂 speaker_encoder，内部 transpose(1,2)→[batch,128,mel_frames]） |

### 序列布局（单样本，T 方向）
```
pos:  [0..2]   [3..7]                          [8 .. 8+text_len-3)        [...]        [8+text_len-2]      [8+text_len-1 .. ..+codec_len)   [..+codec_len]
文本: text[:3]  pad pad pad pad pad            text[3:] / eos              pad          pad                 pad (目标音频帧)                   pad
codec: 0       nothink think_bos think_eos 0 pad  pad...                     pad          codec_bos            audio_codec_0 (码本0)              codec_eos
                                                    ↑ speaker_emb 注入 position 6（codec 通道嵌入后的张量）
```
- 前 8 位是固定头：3 个文本 token + `[codec_nothink_id, codec_think_bos_id, codec_think_eos_id, 0(speaker 槽), codec_pad_id]`。
- 目标音频帧接在文本之后；`codec_0_labels` 只在目标音频帧位置有值，其余 -100。

## 5. 训练循环（官方 `sft_12hz.py`，2 段 forward）

```
for batch in dataloader:
    # ① speaker_encoder 前置（独立前向，detach 冻结）
    speaker_embedding = model.speaker_encoder(ref_mels).detach()
    if target_speaker_embedding is None: target_speaker_embedding = speaker_embedding

    # ② 手动组装 inputs_embeds（不走 model(input_ids=...)）
    input_text_ids  = input_ids[:, :, 0]
    input_codec_ids = input_ids[:, :, 1]
    input_text_embedding  = talker.model.text_embedding(input_text_ids)  * text_embedding_mask
    input_codec_embedding = talker.model.codec_embedding(input_codec_ids) * codec_embedding_mask
    input_codec_embedding[:, 6, :] = speaker_embedding       # 注入 speaker emb
    input_embeddings = input_text_embedding + input_codec_embedding
    for i in range(1, 16):                                   # 加上码本 1-15 的嵌入
        e = talker.code_predictor.get_input_embeddings()[i-1](codec_ids[:, :, i]) * codec_mask
        input_embeddings += e

    # ③ 第一段 forward：Talker 预测 codebook 0
    outputs = talker(inputs_embeds=input_embeddings[:, :-1, :],
                     attention_mask=attention_mask[:, :-1],
                     labels=codec_0_labels[:, 1:],            # 已 shift
                     output_hidden_states=True)
    # outputs.loss = 码本 0 的 shift+CE（HF 内部完成）

    # ④ 第二段 forward：Code predictor 预测 codebooks 1-15（逐帧）
    hidden = outputs.hidden_states[0][-1]                    # 最后一层 hidden
    talker_hidden = hidden[codec_mask[:, :-1]]               # 取目标音频帧的 hidden
    talker_codec_ids = codec_ids[codec_mask]                # [N, 16]，N=批次内目标帧总数
    sub_logits, sub_loss = talker.forward_sub_talker_finetune(talker_codec_ids, talker_hidden)

    # ⑤ 总 loss
    loss = outputs.loss + 0.3 * sub_loss
    accelerator.backward(loss)
    clip_grad_norm_(1.0); optimizer.step(); zero_grad()
```

### 关键超参（官方）
- 全参数 SFT：`AdamW(qwen3tts.model.parameters(), lr=2e-5, weight_decay=0.01)`，bf16，`gradient_accumulation_steps=4`。
- ⚠️ 本项目改 **LoRA**（挂 talker + code_predictor 线性层，冻结 speaker_encoder + embedding 表，见第 7 节）——偏离官方全量 SFT 基线，需实测验证。

### `loss_function` 是什么
- Talker 和 Code predictor 都调 `self.loss_function(logits, labels, vocab_size)`，**继承自 `transformers.PreTrainedModel`**（现代 HF 即 `ForCausalLMLoss`：shift + `F.cross_entropy(ignore_index=-100)`），模型文件里未自定义。
- ✅ W-4 已实测确认 **off-by-one**（transformers 5.14.1，见 `tts/qwen3/loss.py` + `tests/test_loss.py`）：Code predictor 的 stacked logits 是 `[N, 15, V]`（3D），labels `[N, 15]`。继承的 `ForCausalLMLoss` 在最后一轴做标准 LM shift（`pad(labels,(0,1),-100)[...,1:]`）——但 code_predictor 的码本轴**不是时间轴**：序列 `[talker_h, cb0, ..., cb14]` 的 next-token 已体现在"pos(j+1) 输入码本 j emb、head 读 pos(j+1) hidden 预测码本 j+1"，labels=`codec_ids[:,1:]` 已是 head 预测目标序列，应**同位配对**（`logits[:,j] ↔ labels[:,j]=码本 j+1`）。强制 shift 会让 head j（预测码本 j+1）错配到码本 j+2 的 label，且 cb15 的预测被末位 -100 pad 吞掉（不算 loss），且 cb1 监督被首切丢失（`labels[...,1:]` 丢 `labels[:,0]=cb1`）——**双重偏移**（数据 `codec_ids[:,1:]` 已预对齐 `labels[:,j]=cb[j+1]` + `ForCausalLMLoss` 再 shift）。**这是 Qwen3-TTS 官方 bug**（`forward_sub_talker_finetune`→`code_predictor.forward_finetune`→`ForCausalLMLoss`，会话9 Task agent 读 `modeling_qwen3_tts.py:1612-1633` 源码确认），待本项目做完有 WER/SIM 证据时提 bugfix PR。**修正**：Twinkle 的 `Qwen3TTSLoss` 对 code_predictor 段显式写同位 per-head CE（无 shift），`shift_labels` 开关保留复现官方含 shift 供 W-5 对照；talker 段（标准时间轴 `[B,T,V]`）shift 正确，透传 `model.talker.forward` 的 `outputs.loss`。

## 6. 对 W-2/W-3/W-4 的影响（重要）

### 6.1 W-2/W-3（Processor）—— 必须复刻官方双通道布局
- 须产出的 `InputFeature` 等价于第 4 节的 8 个字段，**不是**简单的 `Trajectory + user_data(audio_codes)`。
- Twinkle 现有 `InputProcessor` 对 `[B, T, 16]` 标签有 **3 个结构障碍**（读 `twinkle/src/twinkle/` 源码确认）：
  1. `selective_log_softmax`（`utils/torch_utils.py:62`）单码本，按 `[B,T]` gather——多码本走不了；
  2. `Template._roll_labels`（`template/base.py:339`）`np.roll(axis=-1)`，对 `[T,16]` 滚的是码本轴（错），需滚 `axis=-2`（时间轴）；
  3. `InputProcessor._pad_sequence`（`processor/base.py:476`）对 2D 标签默认 `concat=True`（padding-free 拼接），得 `[1, ΣT, 16]` 而非 `[B, T, 16]`。
- ⇒ 需：自定义 collate（或在 Processor 里直接产出已 pad 的 tensor）+ 把自定义字段加进 `InputProcessor.padding_map` 与 `to_transformers_dict` 白名单（`processor/base.py:31-48, 663-680`），否则被静默丢弃。

### 6.2 W-2 附加（首要难点）—— 自定义 forward 编排
官方训练循环 4 步手动流程（speaker 前置 + inputs_embeds 组装 + 2 段 forward）**超出** Twinkle 标准 `model.forward_backward(inputs=batch, task='causal_lm')` 的范围。该路径假定：单次 `model(**inputs)` 出 `logits`，再 `Loss(inputs, outputs)` 算 loss。而 Qwen3-TTS 需要：
- 前置 speaker_encoder 前向（`.detach()`）；
- 手动组装 `inputs_embeds`（不能 `model(input_ids=...)`）；
- 2 段 forward（Talker → sub_talker），sub_talker 依赖 Talker 的 `output_hidden_states`。
- ⇒ W-2 需设计**自定义 forward 编排**方案，候选：
  - (a) 自定义 `task`（新 Patch，仿 `transformers_fused_ce.py` 的 `TransformersFusedCEPatch`），在 patch 里劫持 forward 做 2 段 + speaker 前置；`task` 机制见 `model/transformers/transformers.py:85-103`（现仅 `causal_lm`/`embedding`/`fused_lm_ce`）。
  - (b) 自定义 `InputProcessor` 子类，在 collate 后注入 speaker 前置 + 组装 `inputs_embeds`；但 2 段 forward 的编排仍需 patch 或改 `forward_backward`。
  - **评估后再定**，倾向 (a)：与 Twinkle 的 task/Patch 范式一致，对上层 cookbook 透明。这是 W-2 首要难点，开发中验证。

### 6.3 W-4（Loss）—— 包 2 段，不是 16 路 CE
- 不是泛化"16 路 CE 求和"，而是 `talker CE(码本0) + 0.3 × code_predictor CE(码本1-15)`。
- 设 `require_logps=False, require_logits=True`（跳过单码本 `selective_log_softmax`，见 `transformers.py:592/617`）；`Loss.__call__(inputs, outputs) -> LossOutput(loss, num_tokens)`（`loss/base.py`）。
- 但若走 6.2 的自定义 forward 编排，loss 可能在编排内部就拼好（`outputs.loss + 0.3*sub_loss`），Twinkle Loss 类退化为"透传编排算好的 loss"——视编排方案而定。
- 注册：从 `twinkle/loss/__init__.py` 导出，cookbook 用 `model.set_loss('TTSMultiCodebookLoss', ...)`（`transformers.py:1058-1071`）。

### 6.4 LoRA 接入位置（已与用户确认）
- LoRA 挂 **talker + code_predictor** 的线性层：`codec_head`、code_predictor 各 `lm_head[i]`、`q/k/v/o_proj`、`gate/up/down_proj`、`text_projection`、`small_to_mtp_projection`。或简化 `'all-linear'`。
- **冻结**：`speaker_encoder`（本就 detach）、`codec_embedding`（码本0 输入表）、`text_embedding`、code_predictor 各 `codec_embedding[i]`（码本1-15 输入表）。
- 与文本 LLM LoRA 完全相通（都是线性层挂补丁），区别只在 forward 编排 + loss。

## 9. 关键认知汇总（一句话记忆）

1. **16 码本 RVQ，但训练是 2 段式**：Talker(AR, 码本0) + Code predictor(深度 Transformer, 码本1-15)，loss=`CE0 + 0.3×CE1-15`。
2. **官方训练循环手动 4 步**（speaker 前置 + inputs_embeds 组装 + 2 段 forward），不走 `model(input_ids=...)`——这是 W-2 首要难点，需自定义 forward 编排。
3. **数据是双通道** `input_ids[B,T,2]` + `codec_ids[B,T,16]` + 4 mask + ref_mels，不是 `Trajectory+user_data`。
4. **本项目 LoRA 挂 talker+code_predictor，冻结其余**；保留 clone 推理，不做 custom_voice 说话人槽。
5. **镜像源以 Qwen3 自带 `finetuning/sft_12hz.py` 为准**（MOSS 仅对比）。
6. **W-2/W-3 在家写+CPU 测，W-5/W-6 去机房跑真训练**（见 `docs/02` 第 4 节 NPU 需求拆分）。
7. **code_predictor loss 有 off-by-one**（W-4 实测）：继承的 `ForCausalLMLoss` 对 `[N,15,V]` 码本轴 shift 错误（head 预测码本 j+1 错配码本 j+2，cb15 被 -100 吞）；`Qwen3TTSLoss` 同位 per-head CE 修正，`shift_labels` 开关保留复现官方供 W-5 对照。talker 段（时间轴）shift 正常透传。

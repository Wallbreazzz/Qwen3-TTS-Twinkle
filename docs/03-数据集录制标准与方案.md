## 1. 两个目标模型对音频格式的硬要求（第一手官方依据）

这是整份标准的"锚点"——录制规格必须先满足目标模型的硬约束，其余都是在它之上求"质量上限"。

### 1.1 Qwen3-TTS-12Hz-1.7B-Base（阿里）

| 项 | 官方硬要求 | 来源 |
|---|---|---|
| 采样率 | **24 kHz**（训练 ref_audio 代码硬断言 `assert sr == 24000`） | `finetuning/dataset.py` ✅ https://github.com/QwenLM/Qwen3-TTS/tree/main/finetuning |
| 声道 | **单声道（mono）**（`librosa.load(x, mono=True)` 强制） | 同上 |
| 位深 | 16-bit WAV（API 接受 WAV/MP3/M4A） | 阿里云百炼 ✅ https://help.aliyun.com/zh/model-studio/voice-cloning-user-guide |
| 零样本克隆参考音频 | API：≥24kHz、单声道、**至少 3 秒连续清晰人声**、推荐 10~20 秒、≤60 秒、≤10MB | 同上 ✅ |
| 训练 manifest 字段 | `{audio, text, ref_audio}` JSONL；**官方强烈建议全数据集用同一条 ref_audio** | `finetuning/README.md` ✅ |
| Tokenizer | `Qwen3-TTS-Tokenizer-12Hz`：16 码本×2048，帧率 12.5Hz | HF 模型卡 ✅ https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-Base |
| 预训练数据规模 | >500 万小时，10 语言 | 技术报告 arXiv:2601.15621 ✅ |

> 大白话：Qwen3-TTS 只吃"24kHz 单声道"。你给它立体声它会强制降混，给它别的采样率它的训练脚本会直接报错（断言）。ref_audio（参考音频）全数据集用同一条——这是克隆场景的官方约定。

### 1.2 MOSS-TTS-Local-Transformer-v1.5（复旦 OpenMOSS）

| 项 | 官方硬要求 | 来源 |
|---|---|---|
| 采样率 | **48 kHz**（原生） | `moss_tts_local_v1.5/README.md` ✅ https://github.com/OpenMOSS/MOSS-TTS/blob/main/moss_tts_local_v1.5/README.md |
| 声道 | **立体声（stereo）**（原生，codec 返回 `[channels, samples]`） | 同上 ✅ |
| Tokenizer | `MOSS-Audio-Tokenizer-v2`（"natively supporting 48 kHz stereo input and output"） | HF ✅；README News 2026.6.7 ✅ |
| 码本 | 12 RVQ 层×1024(10-bit)，帧率 12.5Hz | 同上 ✅ |
| 生成模式 | **Purely Autoregressive (AR)**，时间同步（time-synchronous）调度 | 官方 README 明确写 ✅ |
| 官方微调脚本 | 在 `moss_tts_local/finetuning`（v1.0 为 24kHz；v1.5 需用 Tokenizer-v2 在 48kHz 立体声 tokenize） | README News 2026.3.16 ✅ |

> ⚠️ **重要订正**：本项目 `AGENTS.md`/`docs/00`/`术语表`/`docs/02` 都把 MOSS-Local 写成"非自回归（非 AR）局部 Transformer"。**这是错的**。官方 README 明确 `Generation Mode: Purely Autoregressive (AR)`。"Local"指**时间同步/局部**（每个时间步一次性预测该帧全部 RVQ 层，由 Depth Transformer 建模层间依赖），不是"非自回归"。两个模型都是 AR，只是码本组织与调度不同。**建议后续会话更正项目各文档此措辞**（影响 loss 设计认知）。详见第 9 节。

> ⚠️ **另一订正**：本项目多处把 `community/norwegian-lora/train_lora.py` 当作"MOSS-Local v1.5 的训练脚本"。**它微调的是 `MOSS-TTS`（Delay 8B，24kHz 单声道 32 码本），不是 Local v1.5（48kHz 立体声 12 码本）**。镜像它的 loss 逻辑要小心码本数差异（33 项 vs 12 项）。详见第 9 节。

### 1.3 两个模型格式差异总表

| 维度 | Qwen3-TTS | MOSS-Local-v1.5 | 对录制的影响 |
|---|---|---|---|
| 采样率 | 24 kHz | 48 kHz | 录制 master 应 ≥48kHz，给 Qwen3 下采样到 24k（丢弃 >12kHz，语音主能量<8kHz 可接受） |
| 声道 | 单声道 | 立体声 | **见第 2 节 mono/stereo 取舍决策** |
| 位深 | 16-bit | 未逐项公开（48kHz 立体声） | 录 24-bit master，按需降 16-bit |
| 帧率 | 12.5Hz | 12.5Hz | 相同，无影响 |
| 码本 | 16×2048 | 12×1024 | 不影响录制，只影响 token 组织 |

### 1.4 对照基准：CosyVoice2（案例1反面教材用）

- CosyVoice2 训练 `sample_rate: 24000`，内部会 resample 到 24kHz，对录制采样率容忍度高（≥16kHz 即可）；克隆参考音频要 ≥5 秒连续人声。
- 来源：`examples/libritts/cosyvoice2/conf/cosyvoice2.yaml` ✅；阿里云百炼 CosyVoice 行 ✅。
- 含义：案例1 用 CosyVoice2，门槛低，但它栽在 train=dev/alpha/无评估，不在录制格式。本项目目标模型是 Qwen3-TTS+MOSS，格式要求更严（尤其 MOSS 48kHz 立体声）。

## 2. 录制主格式决策（mono vs stereo）

这是本方案最关键的取舍，先讲清楚再给数值。

### 2.1 矛盾点

- Qwen3-TTS 强制 mono（单声道），立体声会被降混。
- MOSS-Local-v1.5 原生 stereo（立体声），tokenizer 在真实立体声数据上训的。

### 2.2 推荐：录 48kHz / 24-bit / stereo / WAV(PCM) 作为 master

理由：
1. **信息保留最多**：立体声→单声道是"无损方向"（两个通道取平均），可随时降混给 Qwen3；反之 mono→stereo 是"无中生有"（复制通道），信息没增加。
2. **匹配 MOSS tokenizer 原生格式**，避免重采样/降混损失与分布偏移。
3. **单卡 LoRA 微调对存储不敏感**，stereo 双倍数据量在录制阶段无所谓。
4. 若将来只主攻 Qwen3-TTS（不管 MOSS），录 mono 也完全够用——这是可降级的决策。

### 2.3 单说话人立体声的现实

单说话人是"点声源"，单麦录的立体声左右通道高度相关（甚至相同）。真正立体声需要双麦/立体声制式。对纯 TTS 音色克隆，立体声的"声场"意义不大，主要是**满足 MOSS tokenizer 格式**。

> **待阶段0核实**：MOSS-Audio-Tokenizer-v2 对"单麦录 mono 再复制成 stereo"的容忍度未知。若阶段0实测发现复制 stereo 与真 stereo 效果相当，则单麦录 mono master 更省事。**暂按 stereo master 录制**，阶段0验证后再定稿。

### 2.4 派生格式（从 master 生成）

```
master: 48kHz / 24-bit / stereo / WAV
  ├─ 给 MOSS-Local-v1.5: 直接用（48kHz stereo），按需降 16-bit
  └─ 给 Qwen3-TTS: 降混 stereo→mono + 重采样 48k→24k + 降 16-bit
```

命令见第 7 节。

## 3. 录音物理标准（环境/设备/拾音/增益/位深）

> 本节是"录音棚怎么做"的硬规范。每个数值都有出处。

### 3.1 房间声学与混响（RT60）

- **RT60**：声压衰减 60dB 所需时间（ISO 3382）。回声与混响的分界约 50ms——>50-100ms 的单次反射是回声，<50ms 的密集反射是混响。来源：Wikipedia Reverberation ✅。
- **本项目要求：RT60 目标 0.2~0.4 秒**（干，语音清晰度优先；ITU-R BS.1116 听音室约 0.2-0.4s ✅）。
- **绝对禁止**在空旷硬质房间（玻璃/瓷砖/未挂帘大厅）录音——这类房间 RT60 常 >0.8s，模型会把混响尾音学进音色 token 分布，合成语音带"厅堂感"。这是 VALL-E 论文明确警告的：**参考音频若含混响，输出会继承混响**（arXiv:2301.02111 ✅）。
- **最低成本做法**：卧室/衣柜录音，挂厚窗帘、铺地毯、放软沙发吸音；或买 6 块 5cm 聚酯纤维吸音板（约百元）搭 1m² 吸音围挡。

### 3.2 背景噪声控制（NC 评级）

- **NC 曲线**（Noise Curves，ANSI/ASA S12.2-2019）按频谱量化室内背景噪声。主要干扰源是空调/暖通。来源：NTi Audio ✅。
- **本项目要求：NC-15 ~ NC-20**（约 25-30 dBA 等效）。
- **操作**：录时关空调、关风扇、关冰箱、手机静音、关窗；笔记本外接声卡，避免风扇被电容麦拾取。
- **自检**：录 5 秒"空录"（不说话），回放波形应是一条贴近零的细线，**底噪 < -60 dBFS**。

### 3.3 麦克风

- 三类：**电容**（需 +48V 幻象电源，灵敏高、频响宽，棚录首选）、**动圈**（结实耐潮，舞台用，SM58）、**铝带**（figure-8，娇贵）。指向性首选 **cardioid（心型）**正面拾音背面抑制。来源：Wikipedia Microphone ✅。
- **本项目首选**：大振膜电容麦 + cardioid + phantom power（如 Audio-Technica AT2020/AT2035、Rode NT1、铁三角 AT4040，千元级够用）。
- **次选**：USB 电容麦（Rode NT-USB+、Blue Yeti）直连省声卡，底噪略高。
- **避免**：笔记本内置麦、手机麦、动圈麦离嘴太远（信噪比差）。

### 3.4 拾音距离与防喷

- **拾音距离 10-15 cm**（4-6 英寸）。太近有近讲效应（低频提升、闷），太远信噪比下降。
- **角度 45° 侧对麦头**，不正面正对，减少爆破音（"p/b/t"）气流直击振膜。
- **必装防喷网（pop filter）**或防风海绵，离麦 5-8 cm。
- 配麦克风悬臂支架 + 防震架，避免桌面传导振动。
- 对照基准：AISHELL-3（中文多说话人，openslr 93）规范是"高保真麦克风距嘴 20cm、中性情感"（arXiv:2010.11567 ✅）。

### 3.5 增益设置（避免削波）

- **留 headroom**：正常说话峰值落 **-12 ~ -6 dBFS**，最大突发峰值 **不超过 -3 dBFS**，**绝不到 0 dBFS**（0=削波，不可逆失真）。
- 操作：先让说话人以最大音量试读一句，调声卡增益使峰值在 -6 dBFS 左右。
- 监听用**封闭式耳机**（避免回灌），不要用音箱。
- **无直流偏移（DC offset）**：波形中线应贴 0，不整体上移/下移，**DC offset < ±0.5%FS**（满量程的 0.5%）。来源：音频工程惯例（会话A审阅强调"零电平无漂移"）。**为什么**：DC 偏移让能量计算错、削波不对称（先削一边）、codec 编码偏移；多由声卡/接口引入，后期用 ffmpeg `afftdc`/Audacity 去直流。自检：暂停不说话时波形应居中不偏。

### 3.6 位深：24-bit 录、按需降 16-bit

- 16-bit 理论 SNR ≈ 98dB；24-bit ≈ 146dB（实际 21 bit 有效 ≈ 123dB）。公式 SQNR ≈ 1.76 + 6.02b dB。来源：Wikipedia Audio bit depth ✅。
- **本项目录 24-bit**（headroom 充裕，增益设偏也不易削波，且无需 dither）。最终训练集按模型要求决定：Qwen3-TTS 16-bit，MOSS 可留 24-bit。降 16-bit 时加 triangular_hp/shibata dither。

### 3.7 接口/声卡与采样率

- 声卡至少支持 24-bit/48kHz（Focusrite Scarlett Solo、MOTU M2、SSL 2 均可）。监听封闭式耳机。**录制采样率 48 kHz**（主格式）。

### 3.8 统一性铁律（最重要的一条）

> **同一说话人、同一房间、同一麦克风、同一增益、同一时段录完。**

理由：多设备/多环境混录→模型学到"设备特征/房间特征"而非"说话人特征"，克隆/微调后音色漂移。这是 Azure "Consistent volume/speaking rate/pitch" 与本项目 tts-data-pipeline skill 共同强调的。中途换设备=作废重录。

### 3.9 疲劳管理（休息周期）

- **每连续录 15~20 分钟休息一次**（喝水、放松声带 5~10 分钟）。来源：专业音库录制惯例（会话A第5条）。
- **为什么**：声带疲劳后音色变化（发紧、发闷、音量下降），模型会学到"前半段新鲜音色 + 后半段疲劳音色"的不一致分布→音色漂移。与 3.8 统一性铁律同理，都是防"会话内音色漂移"。
- **会话总时长**：单次录制不宜超 2 小时；一天内多会话注意疲劳累积，最好跨天分批。

## 4. 录制内容设计（时长/句数/文本多样性）

> 这一节回答"录多少、录什么内容"。学术共识：**文本多样性 > 纯时长**。

### 4.1 总时长（分级）

| 级别 | 时长 | 用途 | 依据 |
|---|---|---|---|
| 零样本下限 | 3-6 秒 | 不训练，靠参考音频直接克隆 | VALL-E 3s（arXiv:2301.02111✅）、XTTS-v2 6s（HF✅） |
| 少样本微调下限 | <1 分钟 | 达 SOTA 相似度 | YourTTS（arXiv:2112.02418✅） |
| LoRA SFT 最低 | 5 分钟 | smoke test 跑通流程 | 本项目 skill 原值 |
| **LoRA SFT 推荐** | **15-30 分钟** | 高质量微调 | 超 ElevenLabs PVC 30 分钟下限（elevenlabs.io✅）；经典 speaker adaptation 5-30 分钟 |
| 上限 | 不限但重多样性 | 多了边际收益递减 | 学术惯例 |

> 本项目 tts-data-pipeline skill 写"5~15 分钟"。**调研显示 15-30 分钟更稳妥**（超工业 PVC 下限、留余量）。建议：5 分钟做 smoke test，正式 15-30 分钟。

### 4.2 单条句长

- **5-15 秒/句**，句间自然停顿 0.5-1 秒。依据：Azure Custom Neural Voice 分割规范"单句<15秒、停顿0.5-1秒"（learn.microsoft.com ✅）。
- 对照基准：LJSpeech 单条 1.11-10.10s 均值 6.57s（keithito.com✅）；LibriTTS 句级切分。
- 太长（>15s）爆显存，太短（<1s）无上下文——本项目 skill 原"2-15秒"可收紧到"5-15秒"。

### 4.3 文本多样性（比纯时长关键）

- **学术共识**：音色克隆中**音素覆盖/韵律覆盖 > 纯时长**——短而音素均衡的语料优于长但重复的。
- 依据：AISHELL-3 用 218 说话人跨智能家居/新闻/地理多领域文本（arXiv:2010.11567✅）；Emilia 强调多样体裁（脱口秀/采访/辩论/解说/有声书，arXiv:2407.05361✅）。
- **本项目要求文本覆盖**：
  - 中文声母韵母组合尽量全（音素平衡语料，可参考 Harvard/IEEE sentences 思路设计中文版）。
  - 覆盖不同句型（陈述/疑问/感叹）、不同语速、不同语气（平静为主，可含少量情绪）。
  - 避免只录平淡朗读——只录平淡，拟人化上限低（见 `docs/02` 第 5 节微调能力边界）。
- 对照 `docs/02` 第 5.4 节：训练数据要尽量多样，否则 LM 学不到目标人的语速/停顿/语气习惯。

### 4.4 文本来源建议

- 自有业务语料优先（与最终应用场景一致的文本）。
- 否则用公开中文语料库拼句（确保音素覆盖），如 AISHELL-3 文本、Common Voice 中文转写、新闻句。
- 每句独立可读，避免上下文依赖强的长篇连读。

## 5. 质量客观标准（可量化验收）

> 本节是"录完怎么判断合格"的硬阈值。没有单一国际标准强制 TTS 数据 SNR，以下为社区惯例+ITU 标准。

### 5.1 SNR（信噪比）

- 棚录 40-60dB；可接受训练数据惯例 **≥35 dB**。依据：社区惯例；LibriTTS 定性"排除背景噪声显著条目"（openslr 60✅）。
- **本项目要求：≥35 dB，理想 ≥40 dB**。

### 5.2 RT60 混响

- 见 3.1，**<0.4s（干），<0.2s 更佳**。无 TTS 专用国际标准，惯例值。

### 5.3 响度归一化（LUFS）

- **EBU R128**（基于 ITU-R BS.1770，Wikipedia✅）：节目目标响度 **-23 LUFS**（±0.5 LU），True Peak **≤ -1 dBTP**。
- 流媒体目标更低（YouTube/Spotify -14，Apple -16），但**训练集统一用 -23 LUFS** 即可（关键是全数据集一致，绝对值次要）。
- **本项目要求：全数据集归一化到 -23 LUFS，TP ≤ -1 dBTP**。

### 5.4 自动质量筛选（DNSMOS）

- **DNSMOS**（Microsoft，基于 ITU-T P.835 三维框架 SIG/BAK/OVRL 各 1-5）非侵入式打分。DNS 惯例：**≥3 可接受，≥4 良好**（github.com/microsoft/DNS-Challenge✅）。
- Emilia 用 DNSMOS 筛选野外数据，样例保留分 3.0-3.3（arXiv:2407.05361✅）。
- **本项目用法**：录完每条跑 DNSMOS，<3 的条目重录或丢弃。这是"自动质量验收"的客观工具。

### 5.5 客观测量标准参考（ITU 系列，备查）

| 标准 | 性质 | 用途 |
|---|---|---|
| ITU-T P.56 | 活跃语音电平客观测量 | 算 SNR/VAD 的电平依据 |
| ITU-T P.862 (PESQ) | 全参考语音质量感知评估 | MOS 1-5（需干净参考） |
| ITU-T P.863 (POLQA) | PESQ 后继，宽带 | MOS |
| ITU-T P.835 | 三维主观框架 SIG/BAK/OVRL | DNSMOS 的基础 |
| ITU-T P.563 | 单端无参考质量评估 | 低精度，备查 |

> 训练阶段用不上全部；PESQ/UTMOS 主要在阶段3评估合成语音用。录制验收用 SNR+DNSMOS+LUFS 三件套即可。

### 5.6 采样率与重建质量（奈奎斯特）

- 可重建最高频 = 采样率/2：22050→11kHz，24000→12kHz，48000→24kHz。人耳上限 ~20kHz，语音能量主要 <8kHz。
- 含义：22050/24000 对 TTS 语音已足够；48kHz 是为了匹配 MOSS tokenizer，不是为了"更保真"（语音高频本就少）。

## 6. 后处理标准操作（可执行命令）

> 本节给可直接跑的 FFmpeg/SoX/Silero VAD 命令。所有命令已对齐上文标准。

### 6.1 高质量重采样（master→训练格式）

```bash
# 给 Qwen3-TTS：48k stereo → 24k mono 16-bit（soxr Very High Quality）
ffmpeg -i master_48k_24bit_stereo.wav \
  -af "aresample=24000:resampler=soxr:precision=28" \
  -ar 24000 -ac 1 -c:a pcm_s16le out_24k_16bit_mono.wav

# 给 MOSS-Local-v1.5：48k stereo 保留，降 16-bit
ffmpeg -i master_48k_24bit_stereo.wav \
  -af "aresample=48000:resampler=soxr" \
  -ar 48000 -ac 2 -c:a pcm_s16le out_48k_16bit_stereo.wav
```

- 质量损失提示：下采样（48k→24k）丢弃 >12kHz 高频，语音主能量 <8kHz 可接受。**绝不上采样**（16k→24k 是无中生有，Azure 直接拒收 <16k）。

### 6.2 响度归一化（EBU R128，两遍法最准）

```bash
# 单条
ffmpeg -i in.wav -af "loudnorm=I=-23:TP=-1:LRA=11:print_format=json" \
  -ar 24000 -ac 1 -c:a pcm_s16le out.wav

# 批量（社区工具，支持 EBU R128）
ffmpeg-normalize *.wav -t -23 --lra 11 --tp -1 -c:a pcm_s16le \
  -e "-ar 24000 -ac 1" -o normalized/
```
来源：ffmpeg-normalize github.com/slhck/ffmpeg-normalize ✅；EBU R128 Wikipedia ✅。

### 6.3 去噪（轻度，过度伤音色）

- RNNoise 原生 48kHz/16-bit/mono RAW 输入输出（github.com/xiph/rnnoise✅，arXiv:1709.08243）。
- **策略**：能在物理层降噪（关空调、吸音）就别用算法降噪。过度降噪抹掉高频细节/齿音/气息→改变音色→TTS 大忌。
- 确需降噪：RNNoise 轻度，或 FFmpeg `afftdn`：
```bash
ffmpeg -i in.wav -af "afftdn=nt=w:tn=1:nr=12" out.wav  # nr 别拉满
```
- 去混响更要谨慎——房间合格（3.1）根本不需要。

### 6.4 VAD 切分（silero-vad）

- Silero VAD 支持 8000/16000 Hz（github.com/snakers4/silero-vad✅）。
```python
from silero_vad import load_silero_vad, read_audio, get_speech_timestamps
model = load_silero_vad()
wav16k = read_audio('vad_proxy_16k.wav')  # VAD 用 16k 副本探测
ts = get_speech_timestamps(wav16k, model, return_seconds=True,
        threshold=0.5,
        min_speech_duration_ms=250,    # <250ms 丢
        max_speech_duration_ms=30_000, # 超长自动切
        min_silence_duration_ms=100,   # 静音≥100ms 判句尾
        speech_pad_ms=30)              # 前后补 30ms 防截断
# 关键：拿到时间戳后从原始 48k master 按 ts 切片，不从 16k VAD 副本切
```
- 切分目标：5-15 秒短句。

### 6.5 静音裁剪（trim silence）

```bash
# 首尾静音裁剪（-50dB，留 0.1s 起始缓冲）
ffmpeg -i in.wav -af "silenceremove=start_periods=1:start_duration=0.1:\
start_threshold=-50dB:detection=1,areverse,silenceremove=start_periods=1:\
start_duration=0.1:start_threshold=-50dB:detection=1,areverse" out.wav
```
句间静音不裁（自然语流，VAD 已按句切）。

> **首尾静音分层（会话A补强）**：录制时**首尾留 500ms~1s 静音**（给后期裁剪/对齐余量），**成品统一裁到 300ms**。即"录制要求"（留长）≠"成品要求"（裁短），分开写。来源：会话A审阅第1条修正；300ms 是多数 TTS pipeline 的成品 padding 惯例。

### 6.6 立体声降混（给 Qwen3 时）

```bash
ffmpeg -i stereo_in.wav -ac 1 -ar 48000 -c:a pcm_s24le mono_48k_24bit.wav
```
降混后务必重新归一化（降混可能使峰值上升）。

## 7. 转录与对齐标准（文字必须 100% 准）

### 7.1 为什么文字必须准

TTS 训练"教模型读错字"——转录错字/多字/少字，loss 会降（模型在背错的对应）但合成乱码。这是 tts-data-pipeline skill 列的"头号异常症状"，也是 Azure "transcripts must be 100% accurate" 的硬要求（learn.microsoft.com✅）。

### 7.2 流程

1. **ASR 自动转录**：WhisperX（带词级时间戳），中文用 large-v3 模型。
2. **逐句人工校对**：逐句听+对，统一标点/数字读法（如"100"读"一百"还是"一百块"要和录音一致）。
3. **文本与音频完全对齐**：抽查听 10 条确认无错位/截断/多字少字。

### 7.3 对齐验证

- 每条音频时长与文本字数比例应在合理区间（中文约 4-5 字/秒）。
- 异常比例（过长/过短）→ 检查是否有静音/截断/朗读错误。

### 7.4 文本归一化（TN，银行场景重点）

> 本项目客户是银行，话术大量含金额/卡号/日期/英文缩写，**必须规定"怎么读"并写进转写**。会话A审阅第9条指出这是关键缺口。

- **文本归一化（Text Normalization, TN）**：把书面符号转成"实际读音文字"。模型不看符号，要学"怎么读"。
- **银行场景必规定的读法**（举例，需与客户统一口径）：
  - 金额：`¥1,234.56` → 转写写"一千二百三十四元五角六分"（按实际发音）
  - 卡号/账号：`6225 **** 1234` → 逐位读，星号读"星星"或省略（按实际发音）
  - 日期：`2026-08-31` → "二零二六年八月三十一日"
  - 英文缩写：`ATM/APP/USB` → 按字母读或按词读，全集统一
  - 百分比/小数：`3.5%` → "百分之三点五"
- **铁律**：转写与**实际发音逐字对齐**，不是与脚本对齐。说话人读错/加字/漏字时，**改转写不改音频**（会话A审阅第6条强调的最大隐患，单列 QC 规则）。
- 对照：Azure 要求 "transcripts 100% accurate"（learn.microsoft.com✅）。

### 7.5 文件命名与元数据规范

> 便于程序化批量读取、溯源、切分。会话A审阅第10条。

- **命名约定**：`音色ID_语料编号_第n遍_会话ID.wav`，如 `spk001_0007_v2_s03.wav`。
- **同名元数据 JSON**（每条音频一个）：字段含说话人/性别/年龄/采样率/位深/声道/会话ID/文本/是否含数字英文/情绪/录制日期/设备。
- **为什么**：批量训练要程序化配对，命名乱则无法配对音频与文本；元数据便于按维度筛选（如只训平静情绪）。
- 对照：Emilia 数据集每条带 speaker id + dnsmos 质量分（arXiv:2407.05361✅）；本项目 manifest 格式见 tts-data-pipeline skill。

### 7.6 法规与授权（商用前置，不可省）

> 声纹属个人信息/生物识别信息，法律约束严。会话A审阅第8条写得最到位。本项目客户是银行、商用，**必须先签授权**。

- **法律依据**：《个人信息保护法》《民法典》——声纹唯一识别自然人，属敏感个人信息。
- **授权书必须含**：
  - 授权范围：含本项目三模型（Qwen3-TTS / MOSS-Local / CosyVoice 对照）的**商用衍生品**使用。
  - 授权期限：明确起止，到期可撤回。
  - 用途限制：限定用于语音合成微调与服务，不得他用。
  - 可撤回条款：录音人有权在期限内撤回（需约定已训练模型的处理方式）。
- **为什么单列**：技术标准再完善，无授权=非法数据，商用风险。这是录制启动的**前置门槛**，不签不录。

## 8. train/val 拆分与防泄漏（案例1 根因）

### 8.1 案例1 反面教训

案例1（cosyvoice2_train）把 `dev` 直接 `cp` 成 `train`（完全相同）→ val loss ≡ train loss，**看不出过拟合**，只能盲猜 epoch。这是"心里没谱"的根因（见 `cases/案例对比与问题分析.md` P1）。

### 8.2 正确做法

- 拆 **10-20% 不重叠句作 val**；且 **val 文本必须是训练集没见过的**（文本不重复，不只是音频不重复）。
- val 用未参与训练的句子，才能测泛化（而非背诵）。
- 拆分在文本层面做（按句），不按音频条——同一句的不同 take 也算泄漏。

### 8.3 manifest 字段对齐

对齐官方与案例2（见 `docs/02`）：
- **Qwen3-TTS**：`{audio, text, ref_audio}` JSONL（官方✅），ref_audio 全集同一条。
- **MOSS**：`{manifest-train/val, tokenized-dir}`（先 tokenize✅）。
- **本项目统一 manifest**（见 tts-data-pipeline skill）：
```json
{"audio":"wavs/001.wav","text":"今天天气真好。","ref_audio":"wavs/ref.wav","language":"Chinese",
 "audio_codes":[[...shape T×16...]]}
```
> Qwen3-TTS 的 `ref_audio` 保留**路径**（不预编码），训练时加载成 mel 喂 speaker_encoder；`audio_codes` 仅编码目标音频 `[T,16]`。详见 `docs/05` 第 4 节。

## 9. 录制验收清单（checklist，可对照执行）

- [ ] 同一说话人/房间/麦克风/增益/时段（统一性铁律）

- [ ] 无 DC 偏移（<±0.5%FS，暂停时波形居中）
- [ ] 每 15~20 分钟休息（防声带疲劳音色漂移）
- [ ] 24-bit / 48kHz / stereo master

- [ ] master 格式：48kHz/24-bit/stereo/WAV(PCM)
- [ ] 派生：Qwen3 用 24k/mono/16-bit；MOSS 用 48k/stereo

- [ ] 录制首尾留 500ms~1s 静音，成品裁 300ms
- [ ] 总时长 15-30 分钟（smoke test 可 5 分钟）
- [ ] SNR ≥35dB（理想 ≥40dB）
- [ ] DNSMOS ≥3（<3 重录/丢）
- [ ] 响度归一 -23 LUFS，TP ≤-1 dBTP

### 内容层
- [ ] 文本音素覆盖（声韵母组合全）

- [ ] WhisperX 转录 + 逐句人工校对（100% 准，按实际发音非脚本）

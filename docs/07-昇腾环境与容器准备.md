## 2. 镜像选型：ms-swift vs vllm-omni

| 维度 | `quay.io/ascend/vllm-omni:v0.28.0`（推理镜像，卡7在用） | `quay.nju.edu.cn/ascend/ms-swift:v4.5.2-...`（训练镜像，已下载） |
|---|---|---|
| 定位 | **推理**向（vllm 多模态推理） | **微调训练**向 ✅ |
| CANN | 9.1.0（已验证卡7跑通） | **9.1.0**（与卡7一致，driver 兼容已验证） |
| torch / torch-npu | 2.10.0+cpu / 2.10.0.post4 | 2.10.0 / **2.10.0.post2**（同代，兼容 CANN 9.1.0） |
| Python / 系统 | 3.12.13 / （镜像自带） | 3.12 / openEuler 24.03 |
| 训练栈（peft/transformers/deepspeed/datasets/liger） | 缺/被 vllm 钉死，要补+调 | **齐全**（ms-swift 是训练框架，依赖栈含这些） |
| transformers 版本 | vllm 钉死 | **qwen-tts 钉 4.57.3**（会话9 实测：装 qwen-tts 拉 4.57.3 覆盖镜像；twinkle 无版本约束，4.57.3 共存 OK。原选 5.14.1 被 W-5 推翻——Qwen3-TTS 的 modeling 在 qwen-tts 包，transformers 不内置且 config 无 auto_map） |
| 与 Twinkle 契合 | 推理栈，偏 | **同为 ModelScope 训练框架**，依赖栈设计一致，冲突概率低 |

**结论：选 ms-swift 镜像**。理由：同为训练向 + 同为 ModelScope 生态（ms-swift 与 twinkle 同属 modelscope）+ 训练栈齐全 + CANN 9.1.0 与卡7 driver 兼容已验证 + 同事推荐。

**澄清**（符合 AGENTS.md 硬规则）：用 ms-swift **镜像作 base 环境** ≠ 用 ms-swift 框架训练。训练框架层仍是 **Twinkle**（进容器 `pip install twinkle-kit`），ms-swift 框架代码在镜像里但不调用——就像 vllm-omni 镜像里有 vllm 但训练不调 vllm。

### ⚠️ 纠正一个中途的错误结论
会话中曾推断"vllm-ascend/vllm-omni 镜像不能用（torch-npu 对 9.1.0，宿主 CANN 8.x 不匹配）"——**错了**。前提错：以为容器必须用宿主 toolkit CANN，实际模式是**镜像自带 CANN 9.1.0 + 只挂宿主 driver**（driver 兼容 9.1.0，卡7已跑通）。宿主那个 toolkit 8.x 根本没被容器用。两个镜像都能用，ms-swift 更优。

## 3. 容器模式：镜像自带 CANN + 挂宿主 driver（关键认知）

昇腾容器的 CANN 分两部分：
- **CANN toolkit/runtime**（算子库、编译器）：用**镜像自带的 9.1.0**（不挂宿主 toolkit）。
- **driver**（内核模块，跟宿主机内核绑定）：**挂宿主的** `/usr/local/Ascend/driver/`。
- 设备节点：`--device` 挂 `/dev/davinci*` + `davinci_manager` + `devmm_svm` + `hisi_hdc`。

这样镜像自带的 torch-npu（对 CANN 9.1.0）与镜像自带的 CANN 9.1.0 自洽，driver 由宿主提供（宿主 driver 兼容 9.1.0，卡7已验证）。

**验证容器内 CANN 版本**（起容器后跑，应显示 cann-9.1.0）：
```bash
ls /usr/local/Ascend/                                    # 应见 cann-9.1.0 目录 + 软链 cann
cat /usr/local/Ascend/cann-9.1.0/share/info/runtime/version.info  # runtime 版本
env | grep -iE "ascend|cann"                            # ASCEND_HOME_PATH 应指向 cann-9.1.0
python -c "import torch,torch_npu;print(torch.__version__,torch_npu.__version__)"  # torch_npu 2.10.0.post2
npu-smi info | head -3                                   # 能跑=driver 挂上了
```

## 4. 启动训练容器（挂卡7，仿卡7推理容器命令；训练/推理轮换）

```bash
docker run -itd -u 0 --name h00875519_twinkle_train \
  --ipc=host --privileged --network=mynet1400 --cpus=24 --memory=200g \
  --device /dev/davinci0 --device /dev/davinci1 --device /dev/davinci2 --device /dev/davinci3 \
  --device /dev/davinci4 --device /dev/davinci5 --device /dev/davinci6 --device /dev/davinci7 \
  --device /dev/davinci_manager --device /dev/hisi_hdc --device /dev/devmm_svm \
  -v /usr/local/dcmi:/usr/local/dcmi \
  -v /usr/local/Ascend/driver/tools/hccn_tool:/usr/local/Ascend/driver/tools/hccn_tool \
  -v /usr/local/bin/npu-smi:/usr/local/bin/npu-smi \
  -v /usr/local/Ascend/driver/lib64/:/usr/local/Ascend/driver/lib64/ \
  -v /usr/local/Ascend/driver/version.info:/usr/local/Ascend/driver/version.info \
  -v /etc/ascend_install.info:/etc/ascend_install.info \
  -v /root/.cache:/root/.cache -v /home/:/home/ \
  -e ASCEND_RT_VISIBLE_DEVICES=7 \
  quay.nju.edu.cn/ascend/ms-swift:v4.5.2-cann9.1.0-torch_npu2.10.0.post2-910b-openeuler24.03-py3.12 bash
```
- `-e ASCEND_RT_VISIBLE_DEVICES=7`：限定用**卡7**（会话9 实测：卡6 已不可用，只能卡7；训练与推理轮换，不与推理同时）。
- 挂全部 `/dev/davinci0-7` 是访问权（仿卡7已验证模式）；实际只用卡7由 `ASCEND_RT_VISIBLE_DEVICES` 限定。
- `--privileged` 仿卡7（保险）；如想更隔离可改精确 `--device /dev/davinci7` + 公共设备，先按卡7模式跑通。
- 镜像 env 已配好 CANN（进容器不用 `source set_env.sh`）。

## 6. 排障表

| 症状 | 原因 | 处理 |
|---|---|---|
| `kernelize` 报算子未实现 | CANN 9.1.0 与 Twinkle CI 9.0.0 同代，理论兼容；个别算子可能差 | `export TWINKLE_TORCH_BASELINE=1` 跑纯 torch 基线（不融合，慢但能跑） |
| `flash-linear-attention` 编译失败 | aarch64 + torch2.10 编译 | 先 `TWINKLE_TORCH_BASELINE=1` 跳过 FLA；或装预编译 wheel |
| `import torch_npu` 失败 | driver 没挂对 | 检查 `-v /usr/local/Ascend/driver/...` 挂载 + `--device` |
| transformers 版本（4.57.3）与 ms-swift/vllm-ascend 冲突 | ms-swift/vllm-ascend 钉别的版本 | **忽略**——训练用 qwen-tts(4.57.3)+twinkle，不用 ms-swift/vllm-ascend（部署在卡7 推理容器，分开）。pip 的 dep conflicts warning 是镜像其他包的，无影响 |
| 卡6 不可用/卡7 占用 | 共用服务器 | **会话9：只能用卡7**，训练与推理轮换（不同时）；`npu-smi info` 确认卡7 空闲再起训练 |
| HCCL 端口冲突（多进程） | 共用服务器 | Twinkle `ensure_hccl_socket_env` 自动设；或手动设 `HCCL_IF_BASE_PORT` |

## 7. 代码同步（会话9 已用 w5_deploy.sh 解决）

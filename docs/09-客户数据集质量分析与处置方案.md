## 2. 分析方法

**脚本**：`scripts/analyze_dataset_quality.py`
**依赖**：numpy, soundfile（本机已装；scipy/librosa 可选）
**用法**：`python scripts/analyze_dataset_quality.py [--data_dir 路径]`
**输出**：终端报告 + `数据集质量分析报告.txt` + `数据集质量分析报告.json`

### 14 个分析维度

| # | 维度 | 专业名词 | 大白话 |
|---|---|---|---|
| 1 | 采样率 | Sample Rate | 每秒对声波"拍照"多少次 |
| 2 | 位深 | Bit Depth | 每次"拍照"用多少 bit 存波形高度 |
| 3 | 声道 | Channels | 录了几路信号（mono=1路，stereo=2路） |
| 4 | DC偏移 | DC Offset | 声波中线是否偏离零点 |
| 5 | 峰值 | Peak Level (dBFS) | 最大瞬间值，0=削波 |
| 6 | 削波 | Clipping | 采样点是否被"截顶" |
| 7 | 首部静音 | Leading Silence | 开头到第一句人声的时长 |
| 8 | 尾部静音 | Trailing Silence | 最后一句到结尾的时长 |
| 9 | 信噪比 | SNR | 人声多大声、噪声多小声的差值 |
| 10 | 背景噪声 | Noise Floor | 无人说话时的底噪水平 |
| 11 | 单条时长 | Duration | 每条文件多长 |
| 12 | 总时长 | Total Duration | 全部加起来多长 |
| 13 | 音量一致性 | RMS Consistency | 各条之间平均音量差多少 |
| 14 | 文件命名 | Naming | 文件名规则与配对完整性 |

### SNR 计算方法（简述）

把音频按 20ms 切片，计算每片的 RMS（均方根≈平均能量）。取能量最低的 10% 帧作为"噪声估计"，最高的 90% 帧作为"信号估计"，SNR = 20×log₁₀(信号/噪声)。这是近似方法，非 ITU-T P.56 标准，但足以判断"能不能用"。

## 7. 旧标准 vs 新标准差异及对两模型的影响

### 格式差异

| 维度 | 旧标准要求 | 新标准要求 | 本次数据 | 对Qwen3-TTS | 对MOSS-TTS |
|---|---|---|---|---|---|
| 采样率 | 48kHz | 48kHz (master) | 48kHz | ✅ 下采样到24k即可 | ✅ 原生匹配 |
| 位深 | 16bit | 24bit (master) | 16bit | ✅ Qwen3接受16bit | ⚠ 新标推荐24bit |
| 声道 | 未指定 | stereo (master) | mono | ✅ Qwen3强制mono | ❌ MOSS原生stereo |

### 对 Qwen3-TTS：✅ 可用

- 48kHz/mono/16bit → 下采样到24kHz/mono后**完全匹配** Qwen3-TTS 硬要求（`assert sr==24000`、`mono=True`）
- 削波/DC偏移全部合格
- 数据量充足（剔除异常后40~45分钟）
- SNR/噪声边界值需人工判断，但即使全丢也剩40.9分钟

### 对 MOSS-TTS-Local-v1.5：❌ 不可用

- mono → stereo 是"无中生有"（复制通道），MOSS tokenizer 对此容忍度**未知且未验证**（`docs/03 §2.3` 标注"待阶段0核实"）
- 16bit → 无法事后增加位深
- **需按新标准重新录制 stereo/24bit 母带**

### 建议

- 当前数据可直接用于 Qwen3-TTS LoRA SFT（主攻目标）
- 把新标准传给客户：下次按 48kHz/24-bit/stereo 母带录制，一份 master 同时覆盖两个模型
- `docs/03 §6.1` 有现成 ffmpeg 重采样命令，`§6.4` 有 VAD 切分代码

## 8. 真人录制 vs 模型生成数据的意义

客户问"不完美的真人录制是否仍优于模型生成数据"。答案是**是**，理由来自 `docs/02 §5` 和 `docs/03` 引用的论文：

### 理由一：微调是"模仿"不是"创造"（docs/02 §5.2，lines 199-201）

> "LM 学的是你喂的数据分布。训练数据里有的语速/语气/停顿习惯才能学到；数据单一不会无中生有变得有语气。"
> "微调是'模仿'不是'创造'：next-token CE 让 LM 拟合训练数据 token 分布。能学会目标人的习惯，不能凭空生成数据里没有的情感。"

模型生成音频天然缺少真人的微妙韵律（呼吸声、微妙停顿、自然语速波动）。喂模型生成数据 = 让模型学"另一个模型的特征"而非"真人的特征"。

### 理由二：瑕疵会被继承进 token 分布（VALL-E 论文，arXiv:2301.02111）

`docs/03` line 116 引用：

> "参考音频若含混响，输出会继承混响。"

推论（line 489）：

> "背景噪声 → 底噪学进 token，合成带嘶嘶声。"

模型生成音频本身就带有生成模型的瑕疵（codec 编解码失真、不自然韵律、微小金属音），把这些当训练数据喂回去，等于让模型学习"瑕疵本身"。

### 理由三：codec 二次编码叠加失真（docs/02 §3，line 124）

```
真人录音链路：  真人声 → codec编码 → 模型学习                （1次codec失真）
模型生成链路：  真人声 → codec编码 → 模型A生成 → codec解码 → codec再编码 → 模型B学习  （≥2次codec失真）
```

少经过一次 codec = 少叠加一层失真。这是物理事实，不是理论推测。

### 对比总结

| 维度 | 真人录制 | 模型生成数据 |
|---|---|---|
| 韵律自然度 | ✅ 真人自然的语速/停顿/呼吸/微妙起伏 | ❌ 偏"平均"，缺微变化 |
| codec编解码次数 | 1次 | ≥2次 |
| 失真叠加 | 无 | 有（codec artifact叠加） |
| 面客匹配 | ✅ 按面客实际语速/语调/音量录制 | ❌ 模型不知道面客风格 |
| 可控性 | ✅ 可指定语料内容（银行话术） | ❌ 模型生成内容不可控 |
| 噪声特征 | 真实环境噪声（可降噪去除） | codec伪影（不可降噪，是"底子"里的） |

**结论**：即使本次录制有30条SNR边界值的小瑕疵，它仍然是真人声、单次codec、面客匹配的可控数据——这三点是任何模型生成数据都无法替代的。瑕疵可以后处理修复，但"真人味"无法事后注入合成数据。

## 9. "不自然"问题的分析与 LoRA 策略

### 客户反馈

客户听录制后觉得"有点不自然"——这是非专业人员首次进棚录制的正常现象（紧张、念稿感、语速均匀无变化）。

### 后处理能否改善"不自然"？

**基本不能。** 原因是"自然"是韵律和表达层面的综合表现，而后处理是信号处理层面的工具：

| 维度 | 后处理能否改善 | 说明 |
|---|---|---|
| 背景噪声 | ✅ | 降噪去除嘶嘶声 |
| 各条音量忽大忽小 | ✅ | 响度归一化 |
| 录音环境"盒子感" | ⚠ 轻度 | 去混响效果有限 |
| 语速均匀无变化 | ❌ | 没有滤波器能让均匀语速变自然 |
| 语调平淡无起伏 | ❌ | 不能给平淡音调添加自然变化 |
| 停顿不自然 | ❌ | 能删不能在正确位置添加 |
| 说话紧张/不放松 | ❌ | 这是发声状态，DSP无法改变 |

**类比**：后处理是"修照片的滤镜"，能调亮度/对比度/去噪点，但不能把僵硬的姿势改成自然的姿势。"不自然"是姿势问题，不是滤镜问题。

### 关键转折：模型本身就是"自然引擎"

`docs/02 §5`（lines 188, 199-201）的三段话看似矛盾——既说"能改韵律"又说"上限由数据决定"——但恰恰点明了解法：

```
Qwen3-TTS 预训练：500万+小时、10语种、海量自然语音
  → 模型已"懂"什么是自然的语速/语调/停顿/韵律
  → 强大的"自然度先验"

LoRA 微调：50分钟客户录音
  → 在强大基础上"贴一个小补丁"
  → 补丁学的是"这个人的音色身份"（声纹/音色特征）
  → 补丁不会完全覆盖预训练学到的自然韵律
```

**结论**：微调后的模型合成的新句子，**很可能比原始录音听起来更自然**——因为模型生成新句子时，用的是预训练学到的自然韵律 + 录音学到的音色身份，而非照搬录音里的念稿节奏。

### 风险：训练数据风格"带偏"预训练

`docs/02` line 208 已警告：

> "只录平淡朗读，拟人化上限就低。"

如果录音**极度平淡**，LoRA 补丁会往平淡方向拉。风险大小取决于：

| 因素 | 风险高 ←→ 风险低 | 本项目可控性 |
|---|---|---|
| LoRA rank (r) | r大=容量大=更易学平淡 ←→ r小=只学音色 | ✅ 用r=8降低风险 |
| 训练epochs | 多=过拟合平淡 ←→ 少=保留预训练 | ✅ 2-3 epoch起步 |
| 数据量 | 大=影响大 ←→ 小=影响小 | 50min中等，可控 |
| 录音平淡程度 | 极度平淡=高风险 ←→ 有自然变化=低风险 | 需听辨确认 |

### 处置策略

1. **后处理只做技术修复**（降噪/归一化/VAD切分/下采样）——让音频干净统一，不改韵律
2. **LoRA SFT 用保守参数**——r=8、alpha=16、epochs 2-3 起步
3. **合成后听辨对比**——合成语音比原始录音更自然 → 成功；一样不自然 → 降rank/epoch重训
4. **如仍不够自然** → 考虑重录，但指导客户"像平时跟客户说话一样读"，而非"像播音员一样念"

### 判断标准

- 录音"有点紧张但基本是正常说话" → **可行**，保守LoRA即可
- 录音"完全像机器念稿零波动" → **需重录**

建议挑几条代表性录音听一下判断属于哪种情况。
